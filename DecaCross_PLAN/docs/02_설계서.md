| # | 원칙 | 구체적 귀결 |
|---|---|---|

## 3. ★ 호환성 엔진 상세 설계

### 3.1 문제를 정확히 규정하기

이건 새로운 문제가 아니다. **패키지 의존성 해결 문제(dependency resolution)와 동형(isomorphic)이다.**

| 패키지 매니저 | 데카크로스 |
|---|---|
| 패키지 | 플러그인 / 코어 / Java |
| 버전 제약 | `api-version`, `depend`, `mc_range` |
| 플랫폼 제약 | Bukkit / Fabric / Forge 로더 |
| 충돌(Conflicts) | Oraxen ↔ ItemsAdder |
| 제공(Provides) | "커스텀 아이템 프레임워크" |

그러니 **직접 알고리즘을 발명하지 않는다.** 검증된 걸 가져다 쓴다.

### 3.2 채택: PubGrub

**PubGrub**은 Dart pub이 만들고, Rust 생태계의 `pubgrub` crate로 구현되어 **uv(Python)** 가 실사용 중이며 **cargo에 도입하는 것이 Rust 프로젝트 목표로 채택**된 알고리즘이다.

**왜 SAT 솔버가 아니라 PubGrub인가:**

| 항목 | 일반 SAT | PubGrub |
|---|---|---|
| 해 찾기 | 빠름 | 빠름 |
| **실패 설명** | "UNSAT" (쓸모없음) | **derivation tree — "왜 안 되는지" 인간이 읽을 수 있는 유도 과정** |
| 버전 범위 처리 | 인코딩 필요 | 네이티브 |

데카크로스의 핵심 요구는 "되는 조합 찾기"가 아니라 **"안 되면 왜 안 되는지 말해주기"** 다. PubGrub은 그게 본업이다. 이걸 쓰는 순간 §5.3의 "불가 사유 + 최소 수정안"이 공짜로 따라온다.

### 3.3 도메인 → PubGrub 매핑

`pubgrub`은 `Package`와 `Version` 타입, 그리고 `DependencyProvider`를 요구한다. 마크 도메인을 이렇게 매핑한다.

```rust
enum Pkg {
    Root,                      // 사용자의 요구사항을 담는 가상 루트
    Mc,                        // 마인크래프트 버전 그 자체
    Java,                      // Java feature 버전 (8,16,17,21,25)
    Core(CoreKey),             // paper | purpur | folia | fabric | neoforge ...
    Plugin(Slug),              // essentialsx, luckperms, ...
    Api(ApiKind),              // bukkit-api, fabric-api ... (가상)
    Nms,                       // NMS 매핑 버전 (가상)
    RpFormat,                  // 리소스팩 포맷 (가상)
    DpFormat,                  // 데이터팩 포맷 (가상)
    Provides(Capability),      // ★ 배타 제약용 가상 패키지
}
```

**핵심 트릭 1 — 배타를 "가상 패키지 제공"으로 표현**

PubGrub에는 `Conflicts`가 없다. Debian의 `Provides` 기법을 쓴다.

```
ItemsAdder 4.x  →  provides: Provides(CustomItemFramework) @ 1.0.0
Oraxen 1.x      →  provides: Provides(CustomItemFramework) @ 1.0.0
Nexo 1.x        →  provides: Provides(CustomItemFramework) @ 1.0.0
```
한 패키지의 버전은 해결 과정에서 **하나만** 선택되므로, 세 플러그인이 같은 가상 패키지의 같은 버전을 제공하면 **자동으로 셋 중 하나만 뽑힌다.** 별도 충돌 로직이 필요 없다.

같은 기법으로 처리되는 것들:
- `Provides(EconomyProvider)` — EssentialsX / CMI / 기타 경제 플러그인
- `Provides(PermissionProvider)` — LuckPerms / PEX / GroupManager
- `Provides(ChunkGenerator)` — 월드 생성기 계열
- `Provides(AntiCheat)` — 안티치트 중복 = 오탐 폭발

**핵심 트릭 2 — MC 버전에 서수(ordinal)를 부여**

MC 버전은 semver가 아니다. `1.8.9`, `1.21.8`, `26.3`을 문자열이나 semver로 비교하면 **1.21.8 > 26.3** 같은 참사가 난다(2026년 접두사 폐지 때문). 그래서:

```
Mojang version_manifest_v2.json 의 릴리스 순서대로 정수 서수를 부여
  1.8    → 1200
  1.8.9  → 1209
  ...
  1.21.8 → 4108
  26.1   → 4300
  26.3   → 4320   (구간을 띄워 두어 스냅샷/핫픽스 삽입 여지 확보)

McVersion { ordinal: u32, label: String, is_snapshot: bool }
Ord 구현은 ordinal 만 본다 → 범위 연산이 전부 정수 산술이 된다
```
표시는 `label`, 비교는 `ordinal`. 스냅샷은 기본 제외하되 옵트인 가능.

**핵심 트릭 3 — 제약을 "의존성"으로 번역**

`DependencyProvider::get_dependencies(pkg, version)`이 반환하는 것:

```
Root@1.0.0 의 의존성:
    Mc          ∈ [사용자 선택 or 전체]
    Core(paper) ∈ [*]
    Plugin(essentialsx) ∈ [*]
    Plugin(skript) ∈ [>=2.12.0]

Core(paper)@build-62  의 의존성:
    Mc   ∈ [=1.21.8]            ← 빌드가 특정 MC 버전에 묶임
    Java ∈ [>=21]               ← R1
    Api(bukkit) ∈ [=1.21]       ← 이 코어가 제공하는 API 수준

Plugin(essentialsx)@2.21.0 의 의존성:
    Api(bukkit) ∈ [>=1.20, <1.22]   ← R4 (api-version + 실측)
    Java        ∈ [>=17]            ← R1' (class major version 실측)
    Mc          ∈ [>=1.20, <=1.21.8] ← R12 (NMS 참조 있을 때만 좁힘)
    Plugin(vault) ∈ [>=1.7]          ← R6 depend
    Provides(EconomyProvider) ∈ [=1.0.0]

Plugin(protocollib)@5.1.0 의 의존성:
    Java ∈ [>=17, <22]          ← 상한도 존재 (R2)
    Nms  ∈ [=v1_21_R1]          ← 패치 버전까지 고정
```

의존성으로 전부 번역하고 나면, **R1~R12는 별도 코드가 아니라 데이터가 된다.** 규칙이 늘어나도 엔진 코드는 안 바뀐다.

### 3.4 실패 설명 생성기 (`explain`)

PubGrub이 반환하는 `DerivationTree`를 한국어 문장으로 렌더링한다. 이게 제품의 체감 품질을 결정한다.

```
[원시 derivation tree]
  because Plugin(protocollib) >=5.0.0,<5.2.0 depends on Java >=17,<22
  and Core(paper) build-101 depends on Java >=25
  and Root depends on Plugin(protocollib) *
  and Root depends on Mc =26.3
  → no version of Root satisfies

[렌더링 결과]
  ❌ 26.3에서는 ProtocolLib을 쓸 수 없습니다.

     26.3은 Java 25로 실행되는데,
     ProtocolLib 5.1.0은 Java 21까지만 지원합니다.

     해결 방법
     ① ProtocolLib 5.4.0으로 올리기      ← Java 25 지원 (권장)
     ② 마크 버전을 1.21.8로 낮추기        ← 나머지 25개 전부 호환
     ③ ProtocolLib 제외하고 진행          ← 이걸 요구하는 플러그인 2개도 함께 빠짐
                                            (WorldGuard, EssentialsXSpawn)
```

**렌더링 규칙**
1. 원인이 되는 **최소 충돌 집합**만 보여준다 (전체 트리 노출 금지)
2. 항상 **실행 가능한 선택지 2~3개**를 함께 준다. 선택지 없는 에러는 에러가 아니라 벽이다
3. 각 선택지의 **부수효과를 미리 계산해서 명시** ("함께 빠지는 항목 2개")
4. 전문 용어는 괄호로만 (`Java 25 (class major 69)`)

### 3.5 판정 파이프라인 (5단계)

```
입력: { mc?: 버전 or "아무거나", core?: 코어, wants: [콘텐츠…], ram, os, arch }

① NORMALIZE   느슨한 입력 정규화
              "1.21" → [1.21, 1.21.1 … 1.21.8] 로 확장
              "최신" → 스냅샷 제외 최신 릴리스

② PRUNE       명백히 불가능한 후보 제거 (빠른 필터)
              · 로더 계열 불일치 (Bukkit 플러그인 + Fabric 코어)
              · 콘텐츠가 지원하는 MC 버전 합집합 밖

③ RESOLVE     PubGrub 실행
              성공 → 완전한 버전 할당표
              실패 → DerivationTree

④ POST-CHECK  PubGrub으로 표현 안 되는 규칙 (수치·소프트 제약)
              · R8  pack_format 구간 교집합
              · R11 알려진 버그 블랙리스트
              · RAM 하한 추정 (플러그인 수 × 계수 + 월드 크기)
              · 성능 경고 (Folia + 미대응 플러그인)

⑤ SCORE       복수 해가 있으면 순위화
              score = 충족률×0.45 + 검증등급×0.25
                    + 최신성×0.15 + 코어안정성×0.10 + 인기도×0.05
              → 최적안 1 + 대안 2
```

성능 목표: 콘텐츠 30개 기준 **웹(wasm)에서 50ms 이내**. 타이핑하면서 신호등이 즉시 바뀌어야 한다.

### 3.6 신호등 승격 규칙 (정량)

v1.0에서 "🟡→🟢 승격"이라고만 썼던 부분을 수치로 고정한다.

| 등급 | 조건 | 표시 |
|---|---|---|
| 🟢 **검증됨** | CI 검증 통과 **또는** 서로 다른 설치 ID **20건 이상**에서 기동 성공률 ≥ 95% (최근 90일) | "검증됨 · 사례 N건" |
| 🟡 **아마 됨** | 메타데이터상 제약 위반 없음. 실행 데이터 < 20건 | "메타데이터 기준 호환" |
| 🟠 **주의** | 성공률 70~95% **또는** 알려진 부분 이슈(R11 경고급) | "일부 환경에서 문제 보고" |
| 🔴 **안 됨** | 제약 위반 **또는** 성공률 < 70% (10건 이상 표본) | 원인 + 대안 필수 |

**부트스트랩 문제 정면 대응 (v1.0의 최대 허점):**
텔레메트리는 사용자가 있어야 쌓인다. 사용자는 정확도가 있어야 온다. 닭-달걀이다. 해결:

```
Phase 1 출시 시점에 이미 🟢 데이터가 있어야 한다
  → 출시 전 2주간 VERIFIER CI 단독 가동
  → 인기 플러그인 상위 150개 × 최근 MC 12개 버전 × Paper = 1,800 조합
  → GitHub Actions 무료 티어로 야간 배치 (조합당 ~40초 → 20시간/회)
  → 출시일에 🟢 커버리지 60% 확보하고 시작한다
```
**즉 VERIFIER는 Phase 2가 아니라 Phase 1의 선행 과제다.** (기획서 로드맵 수정 필요)

### 3.7 에러 택소노미 — 로그를 해결책으로

`logparse` 크레이트가 로그 라인을 **에러 시그니처**로 정규화하고, 시그니처마다 원인·해결이 붙는다. 이게 F-06/F-24의 실체다.

| 시그니처 (정규식 요지) | 원인 | 자동 해결 |
|---|---|---|
| `Unsupported class file major version (\d+)` | Java 버전 부족 | 요구 Java 자동 산출 → [런타임 전환] 1클릭 |
| `UnsupportedClassVersionError` | 동일 | 동일 |
| `You need to agree to the EULA` | eula.txt 미동의 | EULA 다이얼로그 재표시 |
| `FAILED TO BIND TO PORT` / `BindException: Address already in use` | 포트 충돌 | 사용 중 프로세스 탐지 + 대체 포트 제안 |
| `Could not reserve enough space for object heap` | RAM 할당 > 가용 or 32bit Java | 할당량 재계산 + 64bit 런타임 교체 |
| `OutOfMemoryError: Java heap space` | RAM 부족 / 플러그인 누수 | 증량 제안 + 힙 덤프 유도 |
| `Unknown dependency (\w+)` / `Could not load '.*\.jar'` | 의존 플러그인 누락 | 엔진 재질의 → 누락분 1클릭 설치 |
| `NoClassDefFoundError: net/minecraft/server/v(\w+)` | NMS 버전 불일치 | 해당 MC 버전용 빌드로 교체 |
| `This server is running .* version .* which is not compatible` | 코어/플러그인 API 불일치 | 대체 버전 제시 |
| `Watchdog.*Server thread dump` | 서버 프리즈 | 스택에서 **플러그인 패키지명 추출 → 범인 지목** |
| `Can't keep up!.*(\d+)ms` | TPS 저하 | spark 프로파일 제안 + TPS 그래프 마킹 |
| `Invalid pack_format` / `incompatible resource pack` | 팩 포맷 불일치 | §3.8 리넘버링 제안 |
| `java.net.ConnectException` (라이브러리 다운로드) | 네트워크/프록시 | 미러 폴백 재시도 |
| `Error occurred while enabling (\S+)` | 특정 플러그인 활성화 실패 | 해당 플러그인 격리 + 비활성 후 재기동 제안 |

**설계:** 시그니처는 코드가 아니라 **DB 테이블(`error_signatures`)** 이다. 새 에러가 발견되면 배포 없이 규칙만 추가한다. 매칭 안 된 에러는 익명 수집 → 상위 빈도부터 규칙화.

### 3.8 pack_format 처리 (특수 케이스)

기획서 §5.5에서 확인된 대로, 이 값은 **정수가 아니다.**

```rust
struct PackFormat { major: u32, minor: u32 }   // 1.21.9 이후 "88.0" 같은 형태

// 팩이 선언할 수 있는 것
enum PackDecl {
    Single(PackFormat),                        // pack_format: 34
    Range { min: PackFormat, max: PackFormat },// min_format / max_format
    Supported(Vec<PackFormat>),                // supported_formats
}

// 판정: 선언 구간 ∩ 목표 버전의 포맷 ≠ ∅
```
- 리소스팩 포맷과 데이터팩 포맷은 **별개 컬럼**으로 저장 (같은 버전에서 값이 다름)
- 리넘버링 자동 제안은 **구조 변경 경계를 넘지 않을 때만**. 경계 목록(1.13 평탄화, 1.21.4 아이템 모델 체계 전환 등)은 DB 테이블로 관리
- 경계를 넘는 팩은 "되는 척"하지 않고 🔴 + 수동 마이그레이션 가이드 링크

## 4. 설치 파이프라인 설계

### 4.1 상태 머신

```
                    ┌──────────────────────────────────────┐
                    ▼                                      │
IDLE ─▶ RESOLVE ─▶ PLAN ─▶ FETCH ─▶ VERIFY ─▶ LAYOUT ─▶ CONFIG ─▶ EULA ─▶ READY
         │          │       │         │         │          │         │       │
         │          │       │         │         │          │         │       ▼
         │          │       │         │         │          │         │    RUNNING ⇄ STOPPED
         ▼          ▼       ▼         ▼         ▼          ▼         ▼
       FAILED ◀─────┴───────┴─────────┴─────────┴──────────┴─────────┘
         │
         └─▶ ROLLBACK ─▶ IDLE   (스테이징 삭제, 사용자 폴더 무변화)
```

| 단계 | 하는 일 | 실패 시 |
|---|---|---|
| RESOLVE | 호환성 엔진 실행 → 버전 확정 | 설명 + 대안 제시, 파일 다운로드 전 |
| PLAN | 다운로드 목록·총 용량·소요 시간 산출, 사용자에게 확인 | — |
| FETCH | 병렬 다운로드(동시 4), Range 재개 지원, CAS 캐시 히트 시 스킵 | 3회 재시도 → 미러 → 중단 |
| VERIFY | SHA256 대조, zip 무결성, jar 정적 스캔 | 해시 불일치 = 즉시 중단(변조 의심) |
| LAYOUT | 스테이징 디렉터리에 폴더 구조 생성, blob 하드링크 | 스테이징만 삭제 |
| CONFIG | server.properties / config 파일 작성, start 스크립트 생성 | 동일 |
| EULA | 동의 다이얼로그 → eula.txt | 미동의 시 READY 진입 불가 |
| READY | 스테이징 → 최종 경로 **원자적 rename** | — |

### 4.2 원자성 보장

```
Documents/Decacross/servers/
├─ .staging/9f2c-…/          ← 여기서 전부 조립
└─ my-server/                ← rename 한 번으로 등장

성공: fs::rename(.staging/9f2c, my-server)   // 같은 볼륨 → 원자적
실패: remove_dir_all(.staging/9f2c)          // 사용자 폴더 무오염
```
**기존 서버 업데이트**는 rename이 아니라 스냅샷 후 델타 적용:
```
1. .decacross/snapshots/{ts}/ 에 변경 대상 파일 하드링크 백업
2. 델타 적용 (jar 교체·추가·제거)
3. 시험 기동 → Done 로그 확인
4. 실패하면 스냅샷으로 자동 복원 + "롤백했습니다" 알림
```

### 4.3 CAS(내용 주소 저장소) 캐시

```
%LOCALAPPDATA%\Decacross\cache\blobs\{sha[0..2]}\{sha256}

servers/A/plugins/EssentialsX.jar ─┐
servers/B/plugins/EssentialsX.jar ─┼─ 하드링크 ─▶ blobs/3f/3fa9…
servers/C/plugins/EssentialsX.jar ─┘
```
- 서버 5개를 만들어도 같은 jar는 **디스크에 1벌**
- 하드링크 불가(다른 볼륨·FS) 시 복사 폴백
- GC: 어떤 서버도 참조하지 않는 blob을 30일 후 정리
- Java 런타임도 동일 원리로 버전당 1벌 공유

### 4.4 Java 런타임 관리


## 5. 런처 런타임 설계

### 5.1 프로세스 제어

```
tokio::process::Command
  .stdin(piped) .stdout(piped) .stderr(piped)
  .arg("-jar").arg(core_jar).arg("nogui")

stdout/stderr → 라인 스트림 → logparse → 이벤트 → UI 채널(tauri emit)
UI 명령 입력   → stdin write + "\n"
```
- 바닐라 Swing GUI는 **항상 `nogui`로 끈다** (창 두 개 뜨는 참사 방지)
- `-Dfile.encoding=UTF-8` + 로그 파서도 UTF-8 강제. 한글 채팅이 `???`로 깨지면 한국 사용자는 즉시 이탈한다
- Windows에서는 콘솔 창이 뜨지 않도록 `CREATE_NO_WINDOW`

### 5.2 종료 프로토콜 (월드 손상 방지)

```
정상 종료 요청
 ① stdin ◀ "save-all"            대기 (저장 완료 로그 확인)
 ② stdin ◀ "stop"
 ③ 최대 60초 대기                 ← 대용량 월드는 오래 걸린다
 ④ 미종료 → SIGTERM (Win: CTRL_BREAK)
 ⑤ 추가 30초
 ⑥ 미종료 → SIGKILL + 사용자에게 "월드 손상 가능" 명시 경고

강제 종료 버튼은 ④부터 시작하되, 누르기 전에 경고 모달을 띄운다.
```

### 5.3 크래시 처리 + 루프 차단

```
프로세스 비정상 종료 감지
 → 마지막 200줄 + crash-reports/ 최신 파일 수집
 → logparse 로 시그니처 추출 → 진단 카드 표시
 → 자동 재시작 옵션이 켜져 있으면 재시작

크래시 루프 차단:
  5분 내 3회 비정상 종료 → 자동 재시작 중단
  → "진단 모드" 진입: 플러그인 절반씩 비활성화하며 원인 이분 탐색(bisect) 제안
```
**플러그인 이분 탐색(bisect)** 은 수동으로 하면 30분 걸리는 작업이다. 자동화하면 그 자체로 킬러 기능이다.

### 5.4 로그 파서 설계

```
버전별 로그 포맷
  1.7 이하   [12:03:41 INFO]: message
  1.8+       [12:03:41] [Server thread/INFO]: message
  Paper      [12:03:41] [Server thread/INFO]: [PluginName] message

→ 포맷 자동 감지 후 파서 선택
→ 멀티라인(스택트레이스) 병합: "\tat " / "Caused by:" 로 이어붙임
→ 사망 메시지는 버전별 lang 파일(client.jar 내 ko_kr.json)에서 추출한
   템플릿으로 매칭 → 하드코딩 금지 (D1)
```

### 6.1 두 경로

```

B. 로컬 브리지    http://127.0.0.1:{27565..27575}
```

### 6.2 보안 설계 (여기가 제일 위험하다)

로컬 HTTP 서버를 여는 순간 **임의 웹페이지가 내 PC에 파일을 설치시킬 수 있는 구멍**이 생긴다. 실제로 이런 취약점으로 터진 데스크탑 앱이 여럿 있다.

| 위협 | 대응 |
|---|---|
| 악성 사이트가 `/install` 호출 | **모든 설치는 런처의 네이티브 확인 다이얼로그를 거친다.** 웹은 요청만 할 수 있고 실행은 사용자가 승인 |
| DNS rebinding | `Host` 헤더가 `127.0.0.1:{port}`인지 엄격 검증 + `Origin` 화이트리스트(`https://decacross.kr`) |
| CSRF | `Sec-Fetch-Site` 검사 + preflight 요구(커스텀 헤더 `X-Decacross-Bridge: 1`) |
| 포트 스캔으로 사용자 추적 | `/ping`은 버전 문자열만 반환. 서버 목록·경로·계정 정보 일절 노출 금지 |
| 레시피 변조 | `.dcx`는 해시로 참조, 모든 파일은 SHA256 대조. 서명된 레시피는 배지 표시 |

```
확인 다이얼로그 (네이티브, 웹이 위조 불가)
┌────────────────────────────────────────────┐
│  decacross.kr 에서 설치를 요청했습니다      │
│                                            │
│  서버팩   S.OWL 서바이벌                    │

│           플러그인 12개 · 리소스팩 1개      │
│  용량     약 340 MB                        │
│                                            │
│  ⚠ 외부 URL 직접 다운로드 1건 포함          │
│     (github.com/…/Vault.jar)               │
│                                            │
│         [자세히 보기]  [취소]  [설치]       │
└────────────────────────────────────────────┘
```

### 6.3 jar 정적 스캔

```
zip 열기 → .class 순회
  · 최대 class major version  → 필요 Java 산출 (메타데이터보다 신뢰)
  · 위험 API 문자열 참조 탐지:
      Runtime.exec / ProcessBuilder / URLClassLoader.newInstance
      java.net.Socket (외부 통신) / sun.misc.Unsafe / 과도한 리플렉션
  · 난독화 징후 (의미없는 클래스명 비율)
→ 결과는 **차단이 아니라 배지**. 오탐이 많은 영역이라 차단하면 정상 플러그인이 막힌다
→ 공식 저장소(Modrinth/Hangar) 출처는 배지 면제
→ 마켓 유료 콘텐츠는 심사 통과 필수
```

```jsonc
    "resolved_at": "2026-09-16T12:00:00+09:00",
    "engine": "1.4.2",
    "status": "green",
    "verified_installs": 34
  },

  "signature": {
    "alg": "ed25519",
    "key_id": "dcx-heptagon-01",
    "value": "…"          // 본문 정규화 해시에 대한 서명
  }
}
```

**설계 포인트**
- `"build": "latest-stable"` — 고정 빌드가 아니라 **정책**을 담을 수 있게. 재현성이 필요하면 숫자로 고정
- `variables` + `{{템플릿}}` — 서버팩 하나로 여러 사람이 각자 이름·인원으로 쓸 수 있다. 배포자 입장에서 결정적
- `when` 조건부 — "경제 시스템 쓸래?" 하나로 플러그인 3개가 붙었다 떨어진다
- `trust: external` — 공식 저장소 밖 파일은 설치 다이얼로그에서 명시적으로 경고
- `signature` — 마켓 유료 팩 / 확인된 제작자 배지의 기술적 근거

## 8. 데이터베이스 스키마 (Postgres / Supabase)

```sql
-- ── 버전 기준 정보 ────────────────────────────────────────────
create table mc_versions (
  id            bigserial primary key,
  label         text unique not null,        -- '1.21.8', '26.3'
  ordinal       int  unique not null,         -- ★ 비교는 이걸로
  released_at   timestamptz,
  is_snapshot   boolean default false,
  java_min      int not null,                 -- 21, 25 …
  java_recommended int not null,
  rp_format     numeric,                      -- 리소스팩 (88.0 대응 → numeric)
  dp_format     numeric,                      -- 데이터팩 (별개!)
  nms_version   text,                         -- 'v1_21_R1'
  protocol      int
);

create table cores (
  id bigserial primary key,
  key text unique,                            -- paper|purpur|folia|fabric|neoforge…
  loader_family text,                         -- bukkit|fabric|forge|vanilla
  api_kind text                               -- bukkit-api|fabric-api|…
);

create table core_builds (
  id bigserial primary key,
  core_id bigint references cores,
  mc_version_id bigint references mc_versions,
  build text, channel text,                   -- STABLE|EXPERIMENTAL
  download_url text, sha256 text, size bigint,
  published_at timestamptz,
  unique (core_id, mc_version_id, build)
);

-- ── 콘텐츠 (플러그인/모드/스크립트/팩) ─────────────────────────
create table content (
  id bigserial primary key,
  kind text,                                  -- plugin|mod|script|resourcepack|datapack|world|pack
  slug text, name text,
  source text, source_id text,                -- modrinth|hangar|spigot|url|user
  license text,                               -- ★ 재배포 가능 여부 판단 근거
  redistributable boolean default false,      -- ★ false면 미러링 금지
  author text, downloads bigint, icon_url text,
  unique (source, source_id)
);

create table content_versions (
  id bigserial primary key,
  content_id bigint references content,
  version text,
  file_url text, sha256 text, size bigint,
  java_major int,                             -- ★ 바이트코드 실측값
  api_version text,                           -- plugin.yml
  loaders text[],
  mc_ordinal_min int, mc_ordinal_max int,     -- ★ 서수 구간
  pack_format_min numeric, pack_format_max numeric,
  published_at timestamptz,
  unique (content_id, version)
);

create table content_deps (
  content_version_id bigint references content_versions,
  kind text,                                  -- require|optional|conflict|provides
  target_slug text,                           -- 또는 가상 capability 키
  range text                                  -- '>=1.7'
);

-- ── 호환성 사실 (텔레메트리 + CI) ──────────────────────────────
create table compat_facts (
  id bigserial primary key,
  mc_version_id bigint, core_id bigint, core_build text, java_major int,
  content_version_id bigint,
  result text,                                -- ok|fail
  error_sig text,
  source text,                                -- telemetry|ci|manual
  install_id_hash text,                       -- 중복 집계 방지(익명)
  observed_at timestamptz default now()
);
create index on compat_facts (content_version_id, mc_version_id, result);

create table error_signatures (
  id bigserial primary key,
  pattern text,                               -- 정규식
  category text,
  title_ko text, cause_ko text,
  fixes jsonb,                                -- [{label, action, params}]
  priority int
);

-- ── 레시피 / 마켓 ──────────────────────────────────────────────
create table recipes (
  id bigserial primary key,
  owner uuid references auth.users,
  slug text unique, name text,
  dcx jsonb not null,
  visibility text default 'private',           -- private|unlisted|public
  price int default 0,                         -- 0이면 무료
  installs bigint default 0, forks bigint default 0,
  created_at timestamptz default now()
);
-- RLS: public 이거나 owner 본인만 조회. 유료는 구매 레코드 확인.
```

**핵심 컬럼 둘:** `redistributable` (라이선스 리스크 차단)과 `ordinal` (버전 비교 정합성). 이 둘이 빠지면 나중에 전면 마이그레이션이 필요해진다.

## 9. 수집기(Collector) 설계

| 대상 | 주기 | 비고 |
|---|---|---|
| Paper/Purpur/Folia 빌드 | 15분 | Fill API. **식별 가능한 User-Agent + 연락처 필수** |
| Mojang version manifest | 5분 | 신버전 출시일엔 트래픽이 몰린다. 남들보다 먼저 지원하는 게 홍보 포인트 |
| pack_format 추출 | 신버전 감지 시 | client.jar → pack.mcmeta 파싱 → 리소스/데이터 포맷 분리 저장 |
| Modrinth 인덱스 | 6시간 | facets로 loader × MC 버전 순회 |
| Hangar 인덱스 | 6시간 | |
| Adoptium 릴리스 | 24시간 | |
| jar 메타 분석 | 신규 버전 감지 시 | ↓ |

**jar 분석 파이프라인 (재배포 없음)**
```
다운로드(임시) → zip 열기
  ├ plugin.yml / paper-plugin.yml / fabric.mod.json / mods.toml 파싱
  ├ 전체 .class 의 major version 최댓값 → java_major
  ├ 문자열 상수에서 NMS 패키지 참조 탐색 → nms 고정 여부 판정
  ├ Provides capability 추론 (Vault 등록 여부, 알려진 클래스 시그니처)
  └ sha256 기록
→ **jar 즉시 폐기.** 우리는 메타데이터만 보관하고 파일은 재배포하지 않는다
```

## 10. 터널 아키텍처

### Phase 1 — 서드파티 래핑
playit.gg / ngrok 바이너리를 런처가 관리(다운로드·실행·주소 파싱). 인프라 비용 0, 개발 1주.

### Phase 4 — 자체 릴레이
```
[플레이어] ──TCP──▶ [relay.decacross.kr:  국내 리전]
                            │ 제어채널(인증·세션)
                            ▼
                     [런처 내장 클라이언트] ──▶ [로컬 서버 :25565]
```
- FRP 계열 구조. 제어 채널 + 데이터 채널 분리
- 과금: 릴레이에서 바이트 카운팅 → 충전량 차감

**비용 현실 점검 (중요)**
마인크래프트는 플레이어당 대략 **5~20 KB/s**를 쓴다. 10명이 3시간 놀면 대략 1~2 GB의 릴레이 트래픽이 발생한다. 국내 아웃바운드 트래픽은 싸지 않다.

> **결론: 무료 터널 티어는 "체험"으로만 설계한다** (월 3~5 GB 수준). 이걸 넉넉하게 풀면 사용자가 늘수록 적자가 커지는 구조가 된다. 상시 개방이 필요한 사용자는 포트포워딩 안내 또는 §11의 클라우드 이관으로 유도하는 게 서로에게 낫다.

## 11. "PC를 끄면 서버가 꺼진다" — 정면 대응

v1.0 기획서가 회피했던 근본 약점이다. 숨기지 말고 제품화한다.

| 상황 | 데카크로스의 답 |
|---|---|
| 잠깐 친구랑 논다 | 로컬 실행 + 터널. 이게 기본이고 대부분이 여기 해당 |
| 내가 없을 때도 켜두고 싶다 | **절전 방지 모드** + 예약 실행(요일·시간대 스케줄) |
| 집 PC를 원격으로 켜고 싶다 | **WOL(Wake-on-LAN) + 모바일 원격 시작** — 공유기 설정 가이드 동반 |
| 24/7 상시 서버가 필요하다 | **클라우드 이관 마법사**: 같은 `.dcx`로 `docker-compose.yml` + `systemd` 유닛 + 배포 스크립트 생성 → VPS/오라클 무료 티어/AWS에 그대로 올린다 |

**마지막 항목이 핵심이다.** "우리 걸 쓰세요"가 아니라 "여기까지가 우리가 잘하는 영역이고, 그 다음은 이렇게 넘기세요"라고 말하는 쪽이 신뢰를 만든다. 그리고 이관 마법사 자체가 Pro 기능으로 팔린다.

## 14. 사용자 PC 디렉터리 레이아웃

```
%LOCALAPPDATA%\Decacross\            ← 내부 데이터 (사용자가 안 건드림)
├─ runtimes\temurin-{8,16,17,21,25}-jre\
├─ cache\blobs\{ab}\{sha256}
├─ db\compat.sqlite                   ← 호환성 스냅샷 (오프라인 동작)
├─ logs\launcher-*.log
└─ bridge.lock

%USERPROFILE%\Documents\Decacross\   ← ★ 사용자가 직접 접근 가능한 곳
└─ servers\my-server\
   ├─ .decacross\
   │  ├─ recipe.dcx                  ← 이 서버의 레시피
   │  ├─ manifest.json               ← 설치된 파일 목록 + 해시
   │  └─ snapshots\{ts}\
   ├─ paper-1.21.8.jar
   ├─ plugins\  world\  logs\
   ├─ start.bat                      ← 런처 없이도 실행 가능 (D3)
   ├─ server.properties
   └─ eula.txt
```
서버 폴더를 AppData에 숨기지 않고 **Documents에 평문으로** 둔다. 사용자가 자기 서버 파일에 언제든 접근하고 백업하고 떠날 수 있어야 한다. 이게 락인 없는 신뢰의 실물이다.
