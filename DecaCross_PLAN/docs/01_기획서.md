## 1. 배경 & 문제 정의

### 1.1 현재 마크 서버 구축의 실제 절차

```
1. 마크 버전 결정 → 2. 코어(Paper/Fabric/Forge) 버전 찾기 → 3. 그 코어가 요구하는
Java 버전 확인 → 4. Java 설치(기존 Java와 충돌) → 5. start.bat 메모장 작성
(-Xmx, -Xms, nogui, Aikar flags) → 6. 1차 실행 → EULA 튕김 → 7. eula.txt 수정
→ 8. 재실행 → 9. server.properties 수정 → 10. 플러그인 .jar 수집
→ 11. 플러그인 버전 불일치로 콘솔 빨간 글씨 → 12. 의존 플러그인 추가 설치
→ 13. 리소스팩 pack_format 안 맞아서 "구버전 리소스팩" 경고
→ 14. 포트포워딩 / 하마치 → 15. 친구 접속 실패
```

**15단계 중 최소 6단계가 "버전 불일치"에서 터진다.** 이게 데카크로스가 푸는 문제다.

### 1.2 핵심 통증 (Pain Point)

| # | 통증 | 현재 해법 | 문제 |
|---|---|---|---|
| P1 | 마크 버전 ↔ Java 버전 매핑을 모름 | 구글링 | `Unsupported class file major version` 에러만 보고 포기 |
| P2 | 코어별 다운로드 위치가 제각각 | 사이트 5곳 순회 | Paper/Purpur/Fabric/NeoForge 각각 다른 API |
| P3 | 배치파일을 직접 작성 | 블로그 복붙 | RAM 할당·GC 플래그 이해 못 함 |
| P4 | 플러그인이 내 코어/버전에서 도는지 모름 | 일단 넣고 실행 | 콘솔 에러 → 원인 특정 불가 |
| P5 | 플러그인 의존성(depend) 누락 | 에러 로그 해석 | Vault, ProtocolLib, PlaceholderAPI 등 |
| P6 | 리소스팩/모델링이 서버 버전과 안 맞음 | 포기 | pack_format, CustomModelData 체계 변경 |
| P7 | 외부 접속 개방 | 포트포워딩/하마치 | 공유기 못 만짐, CGNAT 환경이면 불가 |
| P8 | 서버 설정 한 벌을 남에게 못 넘김 | 폴더 통째로 압축 | 용량·경로·Java 환경 다름 |

### 1.3 타깃 사용자

- **1차: 서버 입문자 / 친구끼리 노는 소규모 호스트** (중고등~대학생). 15단계를 3분으로.
- **2차: 마크 컨텐츠 제작자 / 스크립터** (Skript·ItemsAdder 기반 컨텐츠 판매·배포).
- **3차: 서버팩 배포자 / 유튜버** ("이 영상 서버팩 그대로 받아가세요" 한 줄 링크).

## 2. 경쟁 분석 — Server Engine 해부

### 2.1 Server Engine (server-engine.kr) 요약

| 구분 | 내용 |
|---|---|
| 정체 | Flutter 기반 데스크탑(Win/macOS) + 모바일(iOS/Android) 통합 서버 관리 유틸 |
| 개발 | SBXT / XTHEiA (1인 개발) |
| 배포 | v1.1.0 빌드 10120 (2026-01-13) 기준 다운로드 약 18,062회, hotfix 10111(2026-07-05) 4,436회 |
| 강점 | ① GUI 서버 생성·코어 자동 다운로드 ② 실시간 로그 이벤트 시각화 ③ NBT 파싱 기반 플레이어 인벤토리 조회 ④ 월드 인스펙터 ⑤ Tunnel(종량제) ⑥ Trigger(이벤트 자동화·도네이션 연동) ⑦ Remote Network(모바일 원격 제어) ⑧ 포터블 구조 |
| 수익 | 앱 무료 + 터널 데이터 충전(모바일 결제) + 플랜별 티어 차등, 후원(Buy Me a Coffee) 보조 |
| 커뮤니티 | minespace.kr (게시글 조회수 20~100대, 활동 저조), Discord |

### 2.2 Server Engine의 빈틈 (= 데카크로스의 진입점)

| 빈틈 | 설명 | 데카크로스의 답 |
|---|---|---|
| **G1. 콘텐츠가 없다** | 서버 "껍데기"는 만들어주지만 플러그인/스크립트/리소스팩/모델은 사용자가 알아서 구해서 폴더에 넣어야 함 | 웹 **콘텐츠 허브** + 원클릭 설치 |
| **G2. 호환성 검증이 없다** | 코어·버전 선택은 되지만 "이 플러그인이 이 버전에서 도는가"는 검증 안 함 | **버전 호환성 엔진**(핵심 자산) |
| **G3. 앱 전용** | 웹사이트는 Flutter Web SPA 소개/다운로드 페이지에 불과. 검색 유입·공유·SEO 0 | **웹 퍼스트** — 설치 전에 브라우저에서 조립 |
| **G4. 조립 결과를 공유 못 함** | 내 서버 구성을 남에게 링크로 못 준다 | **.dcx 레시피 포맷** + 공유 링크 |
| **G5. 생태계/네트워크 효과 없음** | 커뮤니티 활동량 낮음, 크리에이터 유입 동기 없음 | **크리에이터 마켓**(서버팩 판매·수수료) |
| **G6. 다운로드 장벽** | 뭐가 되는지 보려면 일단 설치해야 함 | 설치 전 웹에서 전체 구성 미리보기 |

### 2.3 포지셔닝

```
                  콘텐츠/생태계 있음
                          ↑
                          |
          [데카크로스]     |
                          |
  로컬 실행 ←─────────────┼─────────────→ 클라우드 호스팅
                          |
   [Server Engine]        |    [Aternos, Minehut, 국내 호스팅사]
   [MCSManager]           |
   [AMP/Pterodactyl]      |
                          ↓
                  콘텐츠/생태계 없음
```

**한 문장 포지셔닝:**
> Server Engine이 "마크 서버용 작업관리자"라면, 데카크로스는 **"마크 서버용 앱스토어 + 설치 마법사"**다.

### 2.4 기타 경쟁자

| 제품 | 유형 | 비고 |
|---|---|---|
| CurseForge / Modrinth App | 모드팩 런처 | 클라이언트 중심, 서버 관리 약함, Paper 플러그인 생태계 약함 |
| Pterodactyl / AMP | 서버 패널 | 리눅스 서버용, 일반 사용자에게 진입장벽 극심 |
| MCSManager | 웹 패널 | 오픈소스, 중국어권 중심, 설치 자체가 어려움 |
| Aternos / Minehut | 무료 클라우드 호스팅 | 광고·대기열·성능 제한, 내 PC를 쓰는 게 아님 |
| PrismLauncher | 클라이언트 런처 | 서버 구축 기능 없음 |

## 3. 제품 구조 — 3레이어

```
┌─────────────────────────────────────────────────────────────────┐
│  ① DECACROSS WEB  (decacross.kr)                                │
│     · 서버 빌더 위저드 (버전→코어→Java→플러그인→팩)             │
│     · 콘텐츠 허브 (플러그인/Skript/모델/리소스팩/서버팩)        │
│     · 실시간 호환성 검사 UI                                     │
│     · 레시피(.dcx) 생성 · 공유 링크 · 크리에이터 마켓           │
└────────────────────────────┬────────────────────────────────────┘
                             │ decacross:// 딥링크
                             │ 또는 localhost 브리지(127.0.0.1:27565)
                             ▼
┌─────────────────────────────────────────────────────────────────┐
│  ② DECACROSS LAUNCHER  (Windows / macOS / Linux 데스크탑)       │
│     · 레시피 해석 → 파일 내려받기 → 폴더 구성 → 실행 스크립트    │
│     · 격리형 Java 런타임 관리 (Java 8/16/17/21/25 병렬 보유)     │
│     · EULA 동의 처리 · server.properties GUI                     │
│     · 내장 콘솔 창 (프로세스 파이프 + 로그 파서)                 │
│     · 터널 개방 → 접속 주소 즉시 발급                            │
│     · 리소스팩 자동 호스팅 (내장 HTTP 서버)                      │
└────────────────────────────┬────────────────────────────────────┘
                             │ 조회 / 검증
                             ▼
┌─────────────────────────────────────────────────────────────────┐
│  ③ COMPATIBILITY ENGINE  (서버 사이드 + 클라이언트 캐시)        │
│     · 버전·코어·Java·플러그인·팩 호환성 그래프 DB               │
│     · 제약 충족 솔버 (SAT 유사) → 가능 조합 산출                │
│     · 크롤러/수집기: Paper·Modrinth·Hangar·Adoptium·Mojang       │
└─────────────────────────────────────────────────────────────────┘
```

**설계 원칙:** 웹은 "무엇을 만들지"를 정하고, 런처는 "그걸 실제로 만든다". 둘 사이의 계약이 **.dcx 레시피**다.

### 4.3 F-03 Java 자동 설치 (격리형)

**원칙: 사용자 시스템 Java를 절대 건드리지 않는다.** `JAVA_HOME`, `PATH` 미수정. 데카크로스 전용 디렉터리에 런타임을 병렬 보관하고, 실행 스크립트에서 **절대경로로 호출**한다.

```
%LOCALAPPDATA%\Decacross\runtimes\
  ├─ temurin-8-jre\
  ├─ temurin-16-jre\
  ├─ temurin-17-jre\
  ├─ temurin-21-jre\
  └─ temurin-25-jre\
```

**버전 매핑 (검증됨):**

| 마인크래프트 버전 | 최소 Java | 비고 |
|---|---|---|
| 26.x (26.1~26.3) | **Java 25** | 2026년부터 Mojang이 `1.` 접두사 폐지 |
| 1.20.5 ~ 1.21.x | **Java 21** | 1.20.5에서 점프 |
| 1.18 ~ 1.20.4 | **Java 17** | |
| 1.17 ~ 1.17.1 | **Java 16** | 유일한 Java 16 구간 |
| 1.12 ~ 1.16.5 | **Java 8** (11도 가능) | |
| 1.8 ~ 1.11.2 | **Java 8** | 1.8.9 하한선 |

> ⚠️ 구버전 모드(Forge 1.12.2 등)는 Java 8이 아니면 튕기는 사례가 있어, 데카크로스는 "최소 버전"이 아니라 **"권장 버전"을 고정 설치**한다. 최신 Java 하나로 전부 돌리려는 시도는 하지 않는다.

**다운로드 소스 — Eclipse Adoptium (Temurin) API v3:**
```
GET https://api.adoptium.net/v3/binary/latest/{feature}/ga/{os}/{arch}/{image_type}/hotspot/normal/eclipse

  feature     : 8 | 16 | 17 | 21 | 25
  os          : windows | mac | linux
  arch        : x64 | aarch64
  image_type  : jre  (JDK 불필요 — 용량 절감)
```
※ 조합이 없으면 404 반환 → 폴백 체인(jre 없으면 jdk, aarch64 없으면 x64+Rosetta) 필요.

### 4.4 F-04 실행 스크립트 자동 생성

**Windows (`start.bat`) 예시:**
```bat
@echo off
title Decacross - %SERVER_NAME%
cd /d "%~dp0"
"%LOCALAPPDATA%\Decacross\runtimes\temurin-21-jre\bin\java.exe" ^
  -Xms4G -Xmx4G ^
  -XX:+UseG1GC -XX:+ParallelRefProcEnabled -XX:MaxGCPauseMillis=200 ^
  -XX:+UnlockExperimentalVMOptions -XX:+DisableExplicitGC ^
  -XX:+AlwaysPreTouch -XX:G1NewSizePercent=30 -XX:G1MaxNewSizePercent=40 ^
  -XX:G1HeapRegionSize=8M -XX:G1ReservePercent=20 ^
  -Dfile.encoding=UTF-8 -Dterminal.jline=false ^
  -jar paper-1.21.8.jar nogui
pause
```

**요구사항:**
- RAM 할당은 시스템 메모리 감지 후 `min(시스템의 50%, 권장 상한)` 제안
- **Aikar's Flags** 프로파일 자동 적용 (RAM 12G 이상/미만에 따라 G1 파라미터 분기)
- `-Dfile.encoding=UTF-8` 필수 (한글 채팅/콘솔 깨짐 방지)
- `nogui`로 띄우고 **콘솔은 데카크로스 창이 담당** (바닐라 Swing GUI 미사용)
- 스크립트는 **런처 없이도 실행 가능**하도록 생성 (락인 방지 → 신뢰 확보)

### 4.5 F-05 EULA 처리

Mojang EULA 동의는 **법적 행위**이므로 몰래 처리하지 않는다.

```
설치 마지막 단계:
  ┌──────────────────────────────────────────────────┐
  │ Minecraft 서버를 실행하려면 Mojang EULA 동의가   │
  │ 필요합니다.  [전문 보기 ↗]                       │
  │                                                  │
  │  ☐ 위 약관을 읽고 동의합니다                     │
  │    (eula.txt 에 eula=true 로 기록됩니다)         │
  └──────────────────────────────────────────────────┘
```
사용자가 체크 → 런처가 `eula.txt` 생성/수정 (`eula=true`). **체크 없이는 설치 완료 불가.** 동의 사실은 타임스탬프와 함께 로컬에 기록. 사용자 대신 자동 동의하는 것이 아니라, "1회 클릭으로 동의를 파일에 반영"하는 구조.

**로그 파서:** 정규식 기반으로 raw 로그 → 구조화 이벤트 변환.

| 이벤트 | 패턴(요지) | UI 표현 |
|---|---|---|
| 접속/퇴장 | `(\w+) joined the game` / `left the game` | 👤 배지 + 플레이어 목록 갱신 |
| 채팅 | `<(\w+)> (.*)` | 💬 말풍선 |

**차별 포인트:** Server Engine은 로그를 "예쁘게 보여준다". 데카크로스는 로그 에러를 **호환성 엔진에 되먹여 해결책까지 제시**한다.
> `❌ ProtocolLib 로드 실패 — Unsupported class file major version 65`
> `→ 이 플러그인은 Java 21 빌드입니다. 현재 서버는 Java 17로 실행 중.`
> `→ [ProtocolLib 5.1.0(Java 17 호환)으로 교체]  [서버를 Java 21로 전환]`

### 4.7 한국 시장 특화 — 글로벌 제품이 절대 안 만드는 것들

Modrinth·CurseForge는 글로벌이라 한국 시장의 구체적 통증을 건드리지 않는다. 여기가 로컬 플레이어의 자리다.

**① 방송 연동 (치지직 / SOOP / 유튜브)**
한국 마크 서버 씬의 큰 축은 스트리머다. 후원 → 인게임 이벤트 연결은 이미 수요가 검증됐고(Server Engine도 Trigger로 대응), 국내에는 숲(아프리카)·치지직 후원/채팅을 다루는 API 서비스와 이를 쓰는 마크 플러그인 선례가 이미 존재한다.
```
[후원 감지] → [변수 추출: 닉네임·금액·메시지] → [가공: 조건 분기]
             → [실행: 명령어 / 몹 소환 / 아이템 지급 / 이펙트 / 디스코드 알림]
```
데카크로스는 이걸 **코드 없이 GUI로 조립**하게 하고, 인기 조합은 **프리셋으로 공유**한다. ("후원 5천원 → 크리퍼 10마리" 같은 프리셋이 그 자체로 콘텐츠가 된다)

**② 플러그인 한글화 번들 (F-41)**
EssentialsX·LuckPerms·WorldGuard 같은 주요 플러그인의 메시지 파일을 매번 손으로 번역하는 게 국내 서버 운영의 통과의례다. 커뮤니티가 관리하는 한글 번역본을 **버전별로 관리해서 원클릭 적용**한다.
- 번역도 콘텐츠다 → 기여자 크레딧 → 커뮤니티 형성의 씨앗
- 글로벌 제품은 절대 안 만든다. 그래서 해자가 된다

**③ 국내 커뮤니티와의 관계 설정**
한국 마크 플러그인·스크립트 유통은 한마포(koreaminecraft.net), 디스코드, 개인 카페로 흩어져 있다. **크롤링이 아니라 제휴**로 접근한다. 제작자가 자기 콘텐츠를 데카크로스에 올릴 이유(설치 통계·버전 호환성 자동 검증·유료 판매)를 먼저 만든다.

**④ 동아리 / 학교 모드**
한 사람이 레시피를 만들면 **부원 전원이 같은 구성을 동시에 설치**한다. 실습·오리엔테이션·학과 행사에서 "각자 알아서 깔아오세요"가 사라진다.
> 검증 채널이 이미 있다 — S.OWL 동아리와 한솥밥 학습공동체에서 **첫 실사용 테스트**를 돌릴 수 있다. Phase 0 인터뷰 20건 중 절반은 여기서 나온다.

**⑤ 서버 홍보 창구 (F-21)**
국내 서버 홍보는 특정 서버 목록 사이트와 디스코드에 의존한다. 데카크로스로 만든 서버는 `decacross.kr/s/{id}` 공개 페이지가 자동 생성되고, 접속 주소·인원·상태가 실시간으로 뜬다. **구축 도구가 곧 유통 채널이 된다.**

## 5. ★ 버전 호환성 엔진 (핵심 자산)

> 사용자가 "가장 중요한 게 버전에 맞는 거"라고 한 부분. 데카크로스의 방어 가능한 해자(moat)는 여기 하나다. 나머지 기능은 전부 복제 가능하다.

### 5.1 호환성 차원 (6축)

```
        ┌─────────────┐
        │  MC 버전    │ 26.3 / 1.21.8 / 1.20.4 / 1.12.2 / 1.8.9 ...
        └──────┬──────┘
   ┌───────────┼───────────┬──────────────┬──────────────┐
   ▼           ▼           ▼              ▼              ▼
┌──────┐  ┌────────┐  ┌─────────┐  ┌───────────┐  ┌──────────┐
│ Java │  │  코어  │  │ 플러그인 │  │ 리소스팩  │  │  데이터  │
│ 8~25 │  │ Paper  │  │ api-ver │  │pack_format│  │   팩     │
│      │  │ Fabric │  │ depend  │  │  오버레이 │  │  format  │
└──────┘  └────────┘  └─────────┘  └───────────┘  └──────────┘
                           │
                    ┌──────┴──────┐
                    ▼             ▼
              ┌──────────┐  ┌───────────┐
              │  Skript  │  │  모델링   │
              │ + addon  │  │ItemsAdder │
              │  버전    │  │Oraxen/Nexo│
              └──────────┘  └───────────┘
```

### 5.2 제약 규칙 (Constraint Rules)

| 규칙 | 형태 | 예시 |
|---|---|---|
| R1 Java 하한 | `java_major >= f(mc_version)` | 1.21.8 → Java ≥ 21 |
| R2 Java 상한 | `java_major <= g(core, mc_version)` | 구버전 Forge는 Java 8 고정 |
| R3 코어 지원 버전 | `mc_version ∈ core.supported[]` | Folia는 1.20+ 만 |
| R4 플러그인 API | `plugin.api_version ⊆ core.api_range` | `api-version: 1.13` 미만은 1.13+ 에서 경고 |
| R5 로더 일치 | `plugin.loader == core.loader_family` | Bukkit 플러그인 ≠ Fabric 모드 |
| R6 의존성 | `∀ d ∈ plugin.depend : d ∈ selected` | Vault, ProtocolLib, PlaceholderAPI |
| R7 버전 범위 의존 | `dep.version ∈ plugin.required_range` | ItemsAdder ≥ 4.0 요구 |
| R8 리소스팩 | `pack.pack_format == format_of(mc_version)` | 불일치 시 클라 경고/미적용 |
| R9 상호 배타 | `¬(A ∧ B)` | Oraxen ↔ ItemsAdder 동시 사용 충돌 |
| R10 Skript 애드온 | `addon.skript_range ∋ skript.version` | skript-reflect, SkBee 등 |
| R11 알려진 버그 | 블랙리스트 테이블 | "X 3.2.1은 Paper 1.21.4에서 청크 깨짐" |
| R12 NMS 의존 | `plugin.nms_version == mc.nms_version` | NMS 직접 접근 플러그인은 패치버전까지 일치 필요 |

### 5.3 솔버 동작

입력: `{목표 MC 버전 or "상관없음"} + {원하는 콘텐츠 목록}`
출력: **실행 가능한 완전 조합** 또는 **불가 사유 + 최소 수정안**

```
알고리즘 (요지)
1. 후보 MC 버전 집합 V 생성
2. 각 v ∈ V 에 대해:
   a. R1~R3 으로 Java·코어 후보 산출
   b. 선택 콘텐츠 각각의 호환 버전 집합 계산 (R4,R5,R8,R10,R12)
   c. 비어있으면 v 탈락, 사유 기록
   d. R6,R7 로 의존성 클로저 확장 → 순환/충돌 검사
   e. R9,R11 로 충돌 쌍 제거
3. 살아남은 조합을 점수화:
     score = (콘텐츠 충족률 × 0.5) + (버전 최신성 × 0.2)
           + (코어 안정성 × 0.2) + (커뮤니티 검증 횟수 × 0.1)
4. 최적안 + 대안 2개 제시
5. 해가 없으면: "무엇을 포기하면 해가 생기는지" 최소 제거 집합 계산
   → "EssentialsX를 빼면 26.3에서 나머지 25개가 전부 동작합니다"
```

**알고리즘 확정 — PubGrub 채택 (v1.1 변경점)**

v1.0에서 "SAT 유사"라고만 적었던 부분을 확정한다. **직접 만들지 않고 `pubgrub`을 쓴다.**
Dart pub이 고안하고 Rust 구현체가 존재하며, **uv(Python 패키지 매니저)가 실사용 중이고 cargo 도입이 Rust 프로젝트 목표로 채택된** 알고리즘이다.

| | 일반 SAT 솔버 | PubGrub |
|---|---|---|
| 해 찾기 | 빠름 | 빠름 |
| **실패 설명** | "UNSAT" — 쓸모없음 | **왜 안 되는지 유도 과정을 반환** |

데카크로스의 진짜 요구는 "되는 조합 찾기"가 아니라 **"안 되면 왜 안 되는지 말해주기"** 다. PubGrub은 그게 본업이라 이 요구가 공짜로 따라온다. 배타 제약(Oraxen ↔ ItemsAdder)은 **가상 패키지 Provides 기법**으로, MC 버전 순서는 **서수(ordinal) 정규화**로 해결한다. 상세 매핑은 설계서 §3.3.

**신호등 승격 기준 (정량 확정)**

| 등급 | 조건 | 표시 문구 |
|---|---|---|
| 🟢 검증됨 | CI 검증 통과 **또는** 서로 다른 설치 20건 이상 · 성공률 ≥95% (최근 90일) | "검증됨 · 사례 N건" |
| 🟡 아마 됨 | 제약 위반 없음, 실행 데이터 20건 미만 | "메타데이터 기준 호환" |
| 🟠 주의 | 성공률 70~95% 또는 알려진 부분 이슈 | "일부 환경에서 문제 보고" |
| 🔴 안 됨 | 제약 위반 또는 성공률 <70% (표본 10건+) | 원인 + **대안 필수** |

**부트스트랩 문제 정면 대응 (v1.0의 최대 허점)**
텔레메트리는 사용자가 있어야 쌓이고, 사용자는 정확도가 있어야 온다. 닭-달걀이다.
> **해결: VERIFIER CI를 Phase 2가 아니라 Phase 1 병행 과제로 앞당긴다.**
> 출시 전 8주간 야간 배치로 `인기 플러그인 150개 × 최근 MC 12버전 × Paper` ≈ 1,800 조합을 실제 기동 검증 → **출시일에 🟢 커버리지 60%를 확보하고 시작한다.** 엔진만 있고 데이터가 없으면 제품이 아니다.

### 5.4 데이터 확보 전략

호환성 데이터는 처음엔 없다. 3단계로 채운다.

**1단계 — 메타데이터 자동 수집 (자동화 100%)**
- `.jar` 내부 `plugin.yml` / `paper-plugin.yml` / `fabric.mod.json` / `mods.toml` 파싱
  → `api-version`, `depend`, `softdepend`, `loadbefore`, `libraries` 추출
- `pack.mcmeta` 파싱 → `pack_format`
- Mojang **version manifest**에서 버전별 client.jar 받아 `pack_format`·NMS 매핑 자동 추출 (하드코딩 금지)
- 바이트코드 `major version` 헤더 읽어 **플러그인이 요구하는 Java 버전 직접 판정** (자칭 메타데이터보다 정확)

| class major | Java |
|---|---|
| 52 | 8 |
| 60 | 16 |
| 61 | 17 |
| 65 | 21 |
| 69 | 25 |

**2단계 — 커뮤니티 텔레메트리 (옵트인)**
- 런처가 서버 실행 성공/실패를 익명 보고: `{mc, core, java, plugin[]+version[], 시작성공여부, 에러시그니처}`
- 실패 시 에러 시그니처(스택트레이스 해시)만 전송 — 개인정보·월드데이터 전송 없음
- **N회 성공 → 🟡을 🟢으로 승격.** 사용자가 늘수록 엔진이 정확해지는 구조 = 네트워크 효과

**3단계 — 샌드박스 자동 검증 (Pro/장기)**
- CI에서 컨테이너로 `코어 × 버전 × 플러그인` 조합을 실제 기동 → 30초 내 `Done (Xs)!` 로그 확인
- 인기 상위 200개 플러그인 × 최근 10개 버전 = 2,000 조합 야간 배치

### 5.5 리소스팩 / 모델링 호환성 — 가장 지저분한 구간

pack_format은 이 프로젝트에서 **가장 함정이 많은 데이터**다. 다음 4가지를 전제로 설계한다.

**① 리소스팩 format ≠ 데이터팩 format**
같은 마크 버전이라도 두 값이 다르다. 예: 1.21 기준 리소스팩 34 / 데이터팩 48. 반드시 **별도 컬럼**으로 관리한다. 이걸 하나로 합치면 반드시 터진다.

**② 값이 불연속적이고 증가폭이 불규칙하다**

| 버전 | 데이터팩 format |
|---|---|
| 1.21 ~ 1.21.1 | 48 |
| 1.21.4 | 61 |
| 1.21.8 | 81 |
| 26.1 ~ 26.1.2 | 101.1 |
| 26.2 | 107.1 |
| 26.3 | 121.0 |

패치 하나에 20씩 뛴다. **선형 보간·추정 금지**, 전부 실측값이어야 한다.

**③ 1.21.9부터 format에 마이너 버전이 붙었다 (예: `88.0`, `101.1`)**
비파괴적 변경 시 마이너만 올린다. 즉 **정수 비교 로직이 깨진다.** semver 유사 파서(`major.minor`)로 다루고, `major` 일치 + `minor >= 요구` 를 호환 판정의 기본 규칙으로 삼는다.

**④ `supported_formats` / `min_format` / `max_format` 범위 지원**
최신 팩은 단일 숫자가 아니라 **범위**를 선언할 수 있다. 오버레이(overlay) 디렉터리로 한 팩이 여러 버전을 동시에 지원하기도 한다. 엔진은 단일값이 아니라 **구간 교집합**으로 판정해야 한다.

**수집 방식 — 하드코딩 절대 금지**
```
piston-meta version_manifest_v2.json
  → 각 버전 client.jar 다운로드
  → 내부 pack.mcmeta 파싱
  → { mc_version, resourcepack_format, datapack_format } 테이블 자동 갱신
  → 신규 버전 출시 시 배치가 자동 반영 (사람 손 불필요)
```

**모델링 관련 추가 규칙**
- `CustomModelData` 기반 모델은 1.21.4 전후로 **아이템 모델 컴포넌트 체계**로 전환되었다. 구버전 팩을 신버전에 그대로 올리면 모델이 통째로 사라진다 → 엔진이 이 전환 경계를 **빨간 경고**로 명시.
- ItemsAdder / Oraxen / Nexo / ModelEngine은 각각 자체 팩 생성기를 가지므로 **상호 배타(R9)** 로 취급, 하나만 선택하도록 강제.
- 팩 업로드 시 format 자동 판독 → 목표 버전과 불일치면 **자동 리넘버링 제안** (구조 변경이 없는 경우에 한함). 구조 변경 구간(예: 1.13 평탄화, 1.21.4 모델 체계 전환)을 넘는 리넘버링은 **제안하지 않는다** — 되는 척하는 게 제일 나쁘다.

### 8.1 구조

```
무료 (Free)                      Pro (월 4,900원 예상)        크리에이터 마켓
─────────────────                ────────────────────         ──────────────
· 서버 무제한 생성                · 다중 서버 동시 실행         · 유료 서버팩 판매
· 코어/Java 자동 설치             · 클라우드 백업 (10GB)        · 플랫폼 수수료 15~20%
· 호환성 검사 (기본)              · 호환성 사전검증 리포트       · 정산 (국내 PG)
· 플러그인 허브 전체              · 자동 스냅샷/롤백
· 내장 콘솔·로그 분석             · 고속 터널 채널
· 터널 무료 티어 (월 N GB)        · 광고 없음
· 서버팩 공유/설치                · 팀 협업 (공동 관리)
                                  · 우선 지원
```

### 8.2 왜 이 구조인가

- **Server Engine은 터널 종량제 단일 수익원**이다. 터널은 트래픽 비용이 그대로 나가 마진이 얇고, 사용자가 playit.gg로 이탈하면 수익이 0이 된다.
- 데카크로스는 **마켓 수수료**를 주축으로 둔다. 한국 마크 씬에는 **Skript 스크립트·커스텀 모델·서버팩 거래가 이미 존재하지만 공식 마켓이 없다** (디스코드·카페 개인거래). 이를 제도권으로 끌어오는 게 가장 큰 기회다.
- 크리에이터가 들어오면 → 콘텐츠가 늘고 → 사용자가 늘고 → 호환성 데이터가 쌓이고 → 엔진이 정확해진다. **복제 불가능한 플라이휠.**

### 8.3 초기 비용 구조 (월 기준 추정)

| 항목 | 초기(0~1천 MAU) | 성장기(1만 MAU) |
|---|---|---|
| Supabase | 무료~$25 | $25~$100 |
| Vercel (웹) | 무료~$20 | $20~$150 |
| 수집기 배치 (Oracle Cloud Free / 소형 VPS) | ~$0 | $20 |
| 터널 릴레이 | $0 (서드파티 연동) | 트래픽 비례 (자체화 시 $100~) |
| 샌드박스 검증 CI | $0 (GitHub Actions) | $50 |
| 합계 | **월 5만원 이하** | 월 40~60만원 |

> 1인 개발 + 기존 스택(Next.js/Supabase) 재사용이라 **초기 고정비가 사실상 0에 가깝다.** 이게 이 프로젝트를 지금 시작할 수 있는 이유.
