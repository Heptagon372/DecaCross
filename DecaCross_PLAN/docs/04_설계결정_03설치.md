# 04. 설계 결정 대장 (코드가 인용하는 식별자)

## 왜 이 문서가 있나

`app/`·`core/` 의 KDoc·주석은 명세와 다르게 간 자리마다 `SCP-…`, `D-I…`, `AE-…` 같은 식별자를 달아 뒀다.
그 식별자들은 세션 스크래치패드의 설계 문서(`DESIGN.md`/`DESIGN2.md`)와 적대적 검토 노트를 가리켰는데,
**그 파일들은 Windows 임시 폴더 정리로 사라졌다.** `grep -rn "SCP-" docs/ prompts/` 는 아무것도 내놓지 않았다.
즉 "문서화된 이탈" 이 실은 **이름표만 있고 근거가 없는** 상태였다. 감사할 수 없는 이탈은 이탈이 아니라 그냥 부채다.

이 문서가 그 근거를 **코드와 테스트에서 역으로 복원한** 결과다. 규칙:

- 한 식별자에 한 줄. 무엇을 정했고, 어디가 그걸 지키는지.
- **★ 열린 결정**(사용자 승인 대기)은 맨 아래 §5 에 모으고, 메모리의 "사용자 결정 대기" 목록과 같이 간다.
- 복원한 문장이 코드와 어긋나면 **코드가 맞다.** 고쳐야 할 것은 이 문서다.
- 새 식별자를 코드에 달면 여기에도 한 줄 쓴다. 근거 없는 이름표를 다시 만들지 마라.

접두사 뜻: `SCP-I*` 설치 파이프라인 결정 / `SCP-F*` 다운로더 결정 / `SCP-<수>` 수집기·분석 결정 /
`D-I*` 03 설계 세부 / `AE-*` 외부 사실(스펙·API 계약)에 근거한 상수·규칙.
